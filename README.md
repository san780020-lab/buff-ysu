## 内容管理入口

打开 [内容管理](https://san780020-lab.github.io/buff-ysu/admin.html)，或点击网站页脚的“内容管理”。不必在 GitHub 编辑文件。

- 33 个管理模块：课程与价格、初试/复试资料、海报、每日一题、视频、经验分享、教材、招生、录取、生源百分比、联系方式、网页整理版，以及各栏目文字和图文。
- 文字直接粘贴到表单；图片可粘贴或上传，自动压缩为 WebP，再用“使用选中素材”放到对应字段。PDF 上传后可以补充正文和配图，优先以网页形式阅读。
- 管理页验证 GitHub 用户必须是 `san780020-lab`，发布由 GitHub API 的仓库写入权限执行。前端不包含令牌；只访问入口不能修改网站。
- 首次需用户手动创建仅授权 `buff-ysu` 的 fine-grained token：Contents 与 Pages 为 Read and write，设置有效期。令牌只放在当前页面内存中，不写入仓库、草稿或 localStorage。不要将令牌发给他人。
- 编辑 → 预览 → 发布全部修改。文字、上传素材与版本号在一个非强制 Git 提交内更新；检测到远端变更会阻止覆盖。Pages 部署完成才提示网站已发布；网络失败与已提交但尚在部署会分别提示。
- 内容草稿可以导出/导入 JSON；未上传的素材二进制不在草稿中，需保留原图，导入后重新上传并替换路径。
- 生源模块强制只接受匿名类别和百分比，不允许人数、院校清单或个人字段；上传区不接受 XLSX / DOCX。所有发布的素材均公开，请事先遮挡个人信息。

详细步骤见 [管理入口使用说明](管理入口使用说明.md)。

管理覆盖数据存储于 `assets/data/managed-content.json`，同步生成 `assets/js/managed-data.js`，后者与其他脚本并行加载，避免增加首屏数据请求等待。每次发布同步更新 HTML 中的数据版本号。修改底层 `content.js` 时须留意：已通过管理页接管的模块以管理数据为准。旧 Issue 宣传方式只在管理页尚未接管宣传时生效；今后建议统一使用管理入口。

## 后续如何更新

最常修改的文件：`assets/js/content.js`。

1. `subjects`：两个专业方向的简介。
2. `courses`：课程名称、适合人群、阶段、课时、资料、服务和价格。`previewTopics` 用于首页卡片，`topics` 用于详情；`pricing` 为各班型价格。`stage` 可用 `initial`（初试）或 `reexam`（复试），`subject` 用 `electrical`、`control` 或 `all`。`poster` 对应海报 ID，`document` 为站内 PDF 路径。
3. `videos`：填写真实视频标题、完整 `https://` 链接及 `cover` 封面路径；`group` 用 `control`（自控）、`extended`（团队其他专业课）、`public`（公共课）。`platform` 用 `bilibili` 或 `douyin`；留空 `url` 展示“视频待上线”。首版采用新标签页打开视频，日后可添加 B 站官方嵌入播放器。
4. `contact`：`people` 列表维护咨询人、角色和 QQ；`qqGroup` 为交流群。还支持公众号、微信、邮箱、B 站和抖音主页。不要填写未公开的私人联系方式。
5. `posters`：维护海报标题、分类、缩略图、原尺寸大图和宽高。图片存放在 `assets/posters/`。
6. `dailyQuestions`：公开题目列表，包含 `id`、`date`、`subject`、`title`、`question`、`image`、`knowledgePoint`、`bilibili`、`douyin`。有多道题时可选择往期题目。答案不应通过隐藏按钮放在公开仓库中；目前只提供跳转到平台观看讲解的入口，没有关注验证。
7. `documents`：维护 PDF 标题、简介、页数、大小与原件选页范围，文件存放在 `assets/documents/`。

首页文案与栏目布局修改 `index.html`；配色与排版修改 `assets/css/design.css`，手机适配修改 `assets/css/responsive.css`，控制原理展示样式修改 `assets/css/control.css`；交互修改 `assets/js/main.js`。`index.html` 中的样式和脚本 URL 带版本参数；更新后可同步递增以刷新缓存。

标签页图标采用蓝底白色 BUFF 标识，提供 SVG、16–256 像素 ICO、PNG 和 Apple 收藏图标。更新图标时同步修改链接的版本参数，减少浏览器缓存旧图标的情况。


## 海报加载优化

海报列表使用轻量 WebP 缩略图；`placeholder` 为内嵌小图，网络请求前也可显示完整画面轮廓。点击后先显示缓存缩略图，再异步解码并切换到 `preview` 清晰预览。悬停或键盘聚焦时仅预取对应预览，切换海报时忽略过期加载结果，加载失败时保留小图并提供重试。未自动请求原始大图，原图通过“打开原图”单独访问，八张原始文件保持不变。

## 每日宣传：粘贴文字与图片即可发布

1. 登录仓库所有者 **san780020-lab**，点击网站底部的 **发布宣传**，或打开 [宣传发布表单](https://github.com/san780020-lab/buff-ysu/issues/new?template=daily-promotion.yml)。
2. 在“宣传内容”第一行写标题，空一行粘贴正文；图片直接粘贴、拖入或上传，等上传完成后点击 **Create / 创建**。
3. GitHub Actions 自动同步宣传，随后 GitHub Pages 构建发布。通常等待数分钟后刷新首页即可。最新宣传替换首页置顶内容，不显示日期。

修改已有宣传：打开自己之前的宣传 Issue，编辑正文并保存，也会重新发布。只修改文字且想保留图片时，不要删除正文里的图片链接。发布失败可在仓库 Actions → 发布每日宣传 查看结果，或手动运行并填写该 Issue 编号。

仅所有者本人创建或编辑、且标题以 `[每日宣传]` 开头的 Issue 可触发发布。访客提交不能修改网站。发布使用 GitHub 内置短期令牌，前端不保存密码或访问令牌；不需要电脑常开。宣传和上传图片均为公开内容。图片最多 12 张，正文最多 20,000 字符，首行标题最多 150 字符。

实现：`.github/ISSUE_TEMPLATE/daily-promotion.yml`、`.github/workflows/publish-promotion.yml`、`scripts/publish_promotion.py`。同步目标只有 `assets/data/daily-promotion.txt`、`assets/data/daily-promotion-images.json`。
